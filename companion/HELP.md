## StreamPulse

Controls a running [StreamPulse](https://github.com/jarbochov/StreamPulse) server.

**Config:** host and port of the StreamPulse server (default `localhost:3000`).

**Actions:** All commands are organized with clear category prefixes for fast, intuitive searching in Companion (e.g. searching "Alert", "Overlay", "Tier", "Poll", "Versus", "Tournament", "Randomizer", "Chat", "Variable", "Timer", "Goal", "Session").

- **Alerts:** Queue control (skip, pause, resume, clear), mute or unmute alert display (toggle), replay the last 1–50 alerts (configurable count, default 1), fire test alert for a rule, fire an alert or announcement (with optional text override), simulate live stream events (follow, sub, resub, gift, bits, donation, raid, channel points), and test external webhooks or Companion button presses directly.
- **Overlay & Pages:** Navigate multi-page overlays (next, prev, first, last, auto-advance), show page by name, enable/disable pages, show/hide entire overlays, video playback control (play, pause, toggle, restart, stop, mute, unmute), cutout punchthrough hole control (toggle, punch, fill), slideshow controls (next, prev, play, pause, toggle), and music overlay toggle.
- **Speaker Badges:** Update a selected profile field, set an OBS audio input name, or show/hide/toggle badge details and call-in mode. Select the badge using its overlay and layer names.
- **Tier Maker (Tier List Studio):** Start voting on an item (auto-selects next unranked item if omitted, configurable duration and consensus mode), lock voting (closes chat voting to freeze votes while keeping consensus displayed for discussion), end vote & place into consensus tier (or discard), cancel active vote, reset all placed items back to unranked queue, and load saved tier list template presets.
- **Polls & Tournaments:** Start polls from saved presets or custom questions (with blind voting and 2x sub multiplier), end/crown winner, extend (+seconds), or cancel active polls; tournament bracket actions to score entrant game wins or round pips, confirm & advance match winners, cycle or pin/unpin active matches, toggle live bracket highlight glow, reset/rollback matches, and launch Poll Tournament match votes; bracket camera focus and section view controls.
- **Randomizer Studio:** Spin the randomizer wheel, vertical roller, or physical card deck with configurable duration, auto-hide, phrases, and winner text; toggle or force elimination on/off; restore removed choices.
- **Chat Bot:** Turn bot on/off/toggle, send chat messages, run bot commands or triggers with arguments, send quotes to chat.
- **Variables & Counters:** Increment/decrement/reset counters, set variable values, roll list or topic. Variable Sets support assignment, clearing, cycling, slot swaps, queue management, entry enablement, and shared rotation controls and settings.
- **Timers & Goals:** Start, pause, resume, reset, add/subtract time, toggle timer overlay visibility, reset/enable/disable goals.
- **Production & Server:** Mark clip candidate moments, pin chat messages as highlights, start/end/archive sessions, reset chat data, restart/stop StreamPulse server.

**Variable Sets:** select a discovered set; slot inputs accept a 1-based number or slot name (`all` clears all), and assignment accepts an entry ID or label (blank clears). Slotless sets use their active entry. Queue removal uses a zero-based index. `set_<id>_rotation` is `on` or `off`, `set_<id>_rotation_entry` is the rotating entry label, `set_<id>_active` is the slotless active entry or slot 1 label, and `set_<id>_slot<N>` gives each slot label. The `variable_set_rotating` and `variable_set_entry_active` feedbacks and rotation toggle presets use live shared state. Older servers without rotation report it as off.

Linked entry and Linked entries role fields follow their links in schedule overlays; they do not assign or change slots in the target set. For tracker buttons, choose **Variable Set: Tracker set level**, **toggle**, or **step level**, then select a discovered set / tracker / catalog item. Choose an owner by entry ID or the current entry in a 1-based slot number or slot name. Set accepts a level; step accepts a signed change. Catalog item tiers define levels, with the tracker's maximum as fallback when no item tiers exist. **Tracker reset** selects the tracker and resets one entry, the entry in a slot, or all owners. Owner and level inputs support Companion variables.

### Targeted entry actions and concurrent operators

- **Set entry field:** select a discovered set/field or the `label`, `enabled`, or `inGroup` entry property, and enter an exact entry ID (not its display label). Text preserves text; JSON accepts typed values. Scalar set fields, including counters/numbers and toggles, are sent as stored strings (`4` becomes `"4"`, `false` becomes `"false"`). The `enabled` / `inGroup` properties are booleans instead; use `true` or `false`. A Linked entries (`ref_list`) value must be an ordered JSON array of entry IDs, for example `["sam","alex"]`; order is preserved. Use dedicated Tracker actions for individual tracker cells.
- **Step entry number:** atomically adds a signed change to either a counter or number field. Simultaneous steps accumulate against the latest saved value unless an expected value is supplied.
- **Expected current value:** optional JSON, parsed after Companion-variable substitution. Quote text (`"Alex"`). Numbers and booleans are converted to scalar field strings or boolean roster flags using the same discovered type rules as values. For example, expected `3` for a score becomes `"3"`; expected `true` for a toggle field becomes `"true"`; expected `true` for the `enabled` property remains `true`. Arrays retain order. For exact formatting differences such as stored score `"3.0"`, supply `"3.0"`, not `3`. Leave blank to intentionally omit the condition.
- **Update entry:** supply a JSON patch with any of `label`, `enabled`, `inGroup`, `values`, `tiers`, for example `{"enabled":false,"values":{"score":5,"lineup":["sam","alex"]}}`. Field values are converted using their discovered types; tracker values must be objects and tiers arrays. This uses one atomic entry edit, never a roster replacement. Its optional expected value must be the **complete entry object returned by StreamPulse**, including existing `values`, flags and tiers. It is not a partial filter and is not type-coerced.
- **Add entry:** accepts an ID, label and optional JSON object for additional properties, such as `{"values":{"score":2},"inGroup":false}`. A duplicate ID is a conflict, not an update.
- **Remove entry:** requires confirmation. Its optional expected value compares the complete saved entry object. Dependencies such as linked selections, trackers, saved displays or explicit overlay source entries block deletion; remove the named references in StreamPulse first.

All text/JSON inputs support Companion variables before parsing. Field discovery accepts StreamPulse's `key` identifiers and legacy `id` identifiers. Failed actions are logged and are not automatically retried; a 409 conflict does not become an unconditional overwrite. Refresh/review the latest state before choosing an explicit retry. No additional polling, variables or feedbacks are required.

The module sends JSON **POST** requests to `/api/variables/sets/:setId/entry/set` (`{entry,field,value,expected?}` or `{entry,property,value,expected?}`), `/entry/step` (`{entry,field,delta,expected?}`), `/entry/update` (`{entry,patch,expected?}`), `/entry/add` (`{entry:{id,label,...}}`) and `/entry/remove` (`{entry,expected?}`). IDs are URL-encoded. Success returns the updated set directly; the module refreshes its normal live state. Conflicts return HTTP 409 `{error,code:"conflict",current}` (duplicate entry IDs may omit `current`); blocked deletions return HTTP 409 `{error,code:"dependencies",dependencies:[{kind,id,label}]}`. The API client preserves status/code/current/dependency details while the action logs the human-readable error. Invalid input returns HTTP 400 `{error}`. GET/PATCH equivalents and dependency-check URLs are documented in StreamPulse's `docs/variable-operations.md`.

### Display Library: reusable Inventory, Table and Badge displays

Design management stays in StreamPulse, not Companion. Choose **Table** to arrange schedule rows/columns (including linked Person fields), or **Badge** to design reusable person/member cards. Badge styling now lives in Display Library rather than the overlay inspector. Place these designs as Saved Displays and choose all rows, active entry, occupied slots, grouped entries or explicitly ordered rows as appropriate. Existing Variable Set assign/advance/group actions change the data being followed; they do not edit the shared design.

For Inventory progress, use the existing Tracker actions:

1. In StreamPulse, create an Inventory catalog and a Person Variable Set with a Tracker (checklist) field targeting that catalog. Give each Person their own roster entry. In a Schedule set, link the P1 and P2 roles to the appropriate Person entries.
2. Open `/variable-displays.html` and save an Inventory design for that catalog. Configure its image/label fields, item ordering, groups/sections, flow grid or fixed cells, and styling there.
3. In Custom Overlay Builder, add two `data-display` placements referencing the same saved design. Configure each placement's source to follow the Schedule's active entry, a selected Schedule slot, or a fixed Schedule entry, then one linked-entry role: P1 for the first placement and P2 for the second. Reference traversal supports up to four links; the resolved Person must have a Tracker matching the design's catalog. The design is shared; source selection belongs to each placement.
4. Add a **Variable Set: Tracker set level**, **toggle**, or **step level** button in Companion. In **Tracker item**, select the **Person set / Tracker field / catalog item**, not the Schedule set. Set **Owner** to **Entry ID** and enter P1's actual Person entry ID (for example `person-a`). Duplicate the button with P2's distinct Person entry ID (for example `person-b`). Set accepts an integer level; toggle switches progress and step applies a signed level change.
5. Press P1's button: only that Person's progress changes; P2's remains independent even though both placements use the same design. StreamPulse's operator controls and Companion update the same Tracker progress. No Person slots or Schedule links are assigned or changed by these Tracker actions. Two roles pointing to the same Person intentionally share progress.
6. To clear progress, use **Variable Set: Tracker reset**, choose the Person Tracker, select **Entry ID**, and enter the intended Person ID. **All entries** resets every owner of that Tracker, not just the displayed P1/P2.

Companion does not resolve a placement's Schedule/role chain for Tracker buttons. Keep entry-ID buttons aligned with the linked people, or supply the resolved Person ID through a Companion variable. **Current entry in slot** is an alternative only when the intended Person is already assigned to a slot in the **Person** set; it does not follow a Schedule slot or P1/P2 role. Viewing an Inventory placement does not populate Person slots.

Tracker choices already discover checklist fields and catalog items from Variable Sets; no new element picker is needed. Progress continues through `variables-update` and existing HTTP fallback. Display definitions are separate studio data: `GET /api/variable-displays` returns `{displays, revision}`, `GET /api/variable-displays/:id` reads a design, and `variable-displays-update` carries `{displays, revision}`. The lightweight `/api/status` field `variableDisplaysRevision` is metadata, not progress. Companion does not fetch or edit these definitions, add a background request, or expose design CRUD as on-air actions. Shared design edits affect every placement using that design without changing their sources.

**Variable Groups & Fonts:** use New Group and Manage members in StreamPulse's Variables view. Its grouped tokens use `{{var.theme.accent}}`; group namespaces are lowercase, with spaces/punctuation changed to underscores. Renaming a group or moving a variable changes its placeholder and Number-binding paths: update your saved StreamPulse references yourself; old paths are not aliases. Ungrouped variables and Variable Set tokens are unchanged.

The API returns both `name` (stable identity, e.g. `accent`) and `key` (current placeholder path, e.g. `theme.accent`). Companion variable labels show `key` and refresh with normal live updates; IDs remain `$(streampulse:var_accent)`, based on `name`, so namespace punctuation cannot cause ID collisions. Value/counter/list action name fields take the API name `accent`, not `theme.accent`. The generic placeholder action uses `var.theme.accent`. Use the existing set-variable-value action for font families (e.g. `monospace`); value edits preserve group membership. Uploaded fonts must exist in StreamPulse's Asset Library; group JSON exports do not include files. No extra polling or group actions are added.

**Date, time and duration variables:** create the variable in StreamPulse, then use **Variables: Set a value** with its name and a date, time, local date-time or duration string. Duration examples include `45m` and `1:30:00`; these are static values, not timers. The value is also exposed as `var_<name>`. Linked entries and Trackers are Variable Set fields, not standalone variable types.

**Number variables:** use Number counter controls to increment, decrement or reset. Enable **Use saved Number step** to omit a custom amount; existing buttons keep their explicit amounts. StreamPulse clamps to configured bounds and rounds to stored precision. Reset uses the explicit reset value. Set a value retains these options. Legacy Counter variables and action IDs remain compatible. Overlay-only separators, decimals and affixes do not alter Companion's numeric value.

**Tier Maker Studio:** actions to start votes on specific or next unranked items, freeze/lock voting, lock & place consensus into tier, cancel votes, reset item placements, and load template presets; variables for `tier_voting` ('yes' / 'no'), `tier_vote_status` ('idle', 'active', 'locked'), `tier_item` (current item name), `tier_votes` (total votes cast), `tier_consensus` (winning tier label, e.g. S, A, B), `tier_agreement` (consensus percentage, e.g. 75%), `tier_time` (remaining seconds or 'open'), and `tier_title` (list title); feedbacks for `tier_voting_active`, `tier_vote_locked`, and `tier_consensus_tier` (lights up when leading consensus matches a target tier); ready-to-use button presets for starting votes, locking votes, placing consensus, and cancelling votes.

**Trivia Studio:** start a selected or next question, reveal its answer, clear the current question, navigate, reset the session or played marks, shuffle, load packs, and cast a vote. A duration of zero inherits the studio default for every question; new Start actions/presets default to zero, while existing positive overrides remain unchanged. `trivia_phase` feedback and `trivia_status` follow `idle`, `question`, or `reveal`; question, category, choice count, votes and remaining seconds use the active question. `trivia_correct_answer` and `trivia_correct_letter` are blank until reveal. Chat Voting must be enabled to accept Companion votes; turning it off in StreamPulse also silences automatic trivia chat announcements. Existing action IDs and button options are unchanged.

Reveal Delay waits after the countdown reaches zero, with voting closed and the phase still `question`. Auto-Advance Delay separately holds the revealed answer before advancing. The Reveal action bypasses any pending delay and shows the answer immediately.

**Clear Current Question** hides the question and stops pending transitions without resetting played/done marks. **Randomize Choices** in StreamPulse shuffles live answer order without changing the bank or correct answer; Companion letter votes use the displayed order.

**Feedbacks:** StreamPulse server running (use Invert to flag when it is down), randomizer actively spinning (lights button while wheel or roller spins on stream), tier list voting actively running or locked, tier consensus tier match, timer state, Twitch live, session phase, goal complete or enabled, alert queue paused, alerts muted, music playing, overlay shown, music overlay visible, slideshow playing, paused or open, overlay page enabled, showing now, and auto-advance on.

**Versus & Speedrun Studio:** actions for game scores (`+/-`) and round scores (`+/-`), clock/race control (start, pause, reset, sync start all runners, per-runner finish/toggle/reset for up to 4 runners, speedrun timer display mode `finish` [Main Clock Only — Reveal on Finish + Delta] vs `always` [Always Show Live Runner Timers], None), swap sides, reset scores, queue navigation, preset loading, and Save Progress; variables `matchup_title`, `matchup_c1_score`, `matchup_c1_rounds`, `matchup_c1_time`, `matchup_c1_delta`, `matchup_c1_place`, `matchup_clock`, `matchup_runner_timers_mode`, and more; feedbacks for clock running, runner finished (1–4), and win requirement met.

**Polls & Tournaments:** actions to start polls from saved presets or custom question/choices (with blind voting and 2x sub multiplier), end/crown winner, extend (+seconds), or cancel active polls; tournament bracket actions to score entrant game wins or round pips, confirm & advance match winners, cycle or pin/unpin active matches, toggle live bracket highlight glow, reset/rollback matches, and launch Poll Tournament match votes; variables for `poll_active`, `poll_title`, `poll_total_votes`, `poll_remaining`, `poll_leader`, `poll_winner`, `tournament_title`, `tournament_round`, `tournament_e1_name`, `tournament_e1_score`, `tournament_e1_rounds`, `tournament_e2_name`, `tournament_e2_score`, `tournament_e2_rounds`, `tournament_pending_winner`, `tournament_champion`; feedbacks for `poll_active`, `tournament_active`, and `tournament_win_ready` (lights up when an entrant meets the match win target and is ready to advance).

The Builder overlay element is named **Poll**, not **Twitch Poll**: its shared display service prefers the active native StreamPulse poll, then native results during the configured `resultsSeconds` window, then the latest external Twitch poll. Companion's existing **Polls:** actions still call native `/api/polls/*` endpoints; they do not create or control an external Twitch poll. Do not treat the overlay's fallback choice as a change to Companion action, variable or feedback contracts.

Per-runner finish, toggle, and reset use an explicit zero-based API index for the selected Runner 1–4. Existing buttons retain their runner selection; no reconfiguration is required.

**Presets:** `Spin Randomizer (Wheel / Roller / Deck)` shows the last used mode and duration on the button; `Draw Randomizer Card` is a ready-to-use deck draw button. Both support Studio/overlay inheritance and explicit duration/auto-hide overrides.

### Speaker badges and OBS health

- **Speaker Badge: update profile field** (`speaker_profile`) changes one field at a time: name, avatar (`avatarSrc`), handle, pronouns, call-in location, or call-in status label (`statusText`). Values accept Companion variables. Avatar values can be a public image URL or a StreamPulse media-library path; no upload or full-overlay replacement is needed. Empty values clear optional fields; StreamPulse supplies defaults for an empty name or status label.
- **Speaker Badge: select OBS audio source** (`speaker_audio_source`) sets the exact OBS audio input name, for example `Mic/Aux` or a guest microphone source. The name accepts Companion variables. The OBS connection and Speaker Badges module must be enabled in StreamPulse; Scene Sync is optional.
- **Speaker Badge: set or toggle visibility** (`speaker_visibility`) controls avatar, handle, pronouns, call-in mode or call-in location. These are detail flags, not whole-overlay visibility. Explicit show/hide sends booleans. Toggle reads the current server setting before changing it, so edits made in StreamPulse are respected. Every action sends a minimal PATCH to `/api/custom-overlays/:id/speakers`, preserving unrelated identity, audio, layout and styling fields.
- The `speaker_visibility` feedback lights when the selected detail is visible/enabled; `speaker_identity` matches a profile field against exact text. Ready-to-use presets in **Speaker Badges** toggle each detail and show its current flag. A location flag can be enabled while call-in mode is off; visibility feedback reflects the configured flag, not whether the layer or page is on air.
- Per-badge variables use `speaker_<overlay_id>_<element_id>_` (lowercase, punctuation replaced with underscores), followed by `name`, `avatar`, `handle`, `pronouns`, `location`, `call_in_status`, `audio_source`, `show_avatar`, `show_handle`, `show_pronouns`, `call_in` or `show_location`. Flag values are `yes`/`no`. IDs stay stable when the guest name changes. For example, `$(streampulse:speaker_interview_guest_name)`.
- OBS variables are `obs_connected`, `obs_connecting`, `obs_status`, `obs_scene_sync`, `obs_scene`, `obs_active_engine` and `obs_last_error`. Boolean values are `yes`/`no`; `obs_status` is `connected`, `connecting`, `disconnected`, `disabled`, `error` or `unavailable`. `unavailable` means no OBS snapshot or an unreachable StreamPulse server; `error` means a disconnected OBS connection with a reported error.
- OBS feedbacks are `obs_connected`, `obs_connecting`, `obs_status` (choose a status) and `obs_scene_sync` (choose enabled/disabled). **OBS** presets display connection health and Scene Sync enablement without sending commands. Health follows the existing `/api/status` response; it does not add a separate OBS poll. Speaker audio meters are deliberately excluded from Companion variables and feedback.

Speaker discovery checks controlled custom overlays every 30 seconds. WebSocket `custom-overlay-update` events refresh badge state immediately, and successful Companion changes refresh it from the server response. Newly added badges appear after discovery or a live update; older StreamPulse servers without the speaker endpoint cannot provide these controls.

### Live updates and polling

WebSocket events directly update timers, pages, overlay visibility and speaker badges. Alert, media, Tier Maker and Randomizer events trigger authoritative refreshes coalesced over 100 ms. HTTP fallback refreshes core/live state at the configured polling interval; with WebSocket connected, background refreshes run every five intervals. Lists, presets, chatbot and speaker discovery refresh every 30 seconds, and actions force discovery. Requests run in bounded batches of four. Optional endpoint failures keep their last values; stale responses/events from an older connection cannot overwrite newer state. OBS health clears when the status snapshot is missing or StreamPulse is offline.

### Poll Tournament templates and saved progress

- **Save active bracket as template** stores entrants and settings via `POST /api/polls/tournament/presets` with `{name, fromActive: true}`. **Save progress checkpoint** uses `POST /api/polls/tournament/checkpoints` with `{name}`. Names are optional and accept Companion variables. Both are safe during a running vote and do not change it.
- **Create fresh bracket from template** accepts a template ID. Get IDs from `GET /api/polls/tournament/presets` on your StreamPulse server (open the URL in a browser), then paste the chosen `presets[].id` into the action. On press, Companion fetches the current template and sends only its entrants/settings to `POST /api/polls/tournament/create`; scores, bracket identity and prior progress are not reused.
- **Load saved bracket / checkpoint** accepts a `history[].id` from `GET /api/polls/tournament/history`. Entries include `savedName`, `savedAt`, and `isCheckpoint` to identify saved progress. Companion calls `POST /api/polls/tournament/history/restore` with `{id}`.
- Load/create actions do nothing unless **I confirm this button may replace the current poll bracket** is checked in their configuration. This is a persistent button authorization, not a confirmation dialog on each press. Use dedicated, clearly labeled buttons. The server blocks restore during **any** active vote and blocks fresh creation during a linked bracket vote; rejected requests are logged in Companion.
- Loading replaces the current bracket and archives a replaced started bracket. Completed brackets stay completed; unfinished matches restart voting when launched. Individual voters are never restored.

IDs accept Companion variables. Library lists are deliberately not background-polled: fetch IDs when configuring buttons, and update the ID if its saved entry is removed. Saving new entries does not automatically select them on other buttons.

**Variables:** server online, uptime and start time, randomizer winner (`randomizer_last_winner`), randomizer preset (`randomizer_last_preset`), randomizer mode (`randomizer_last_mode`), last spin duration in seconds (`randomizer_last_duration`), randomizer spinning state (`randomizer_spinning`), choices left in the pool (`randomizer_remaining`), choices removed (`randomizer_removed`), elimination mode (`randomizer_elimination`), session phase, viewers, stream title and category, now-playing track, alert queue (including paused and muted), plus per-timer time and state and per-goal percent and progress, the current page of each multi-page overlay, slideshow position and state, uptime, game details, music position, chat counts, and the latest follower, sub, gift, cheer, donation and raider (with cheer and donation amounts and raid viewer count). Also last chatter and top chatter for the last 5/10/15/30/60 minutes, top hashtags, game developer and rating, clip candidates waiting, session and lifetime followers, subscribers, gift subs, bits and donations, milestones & streaks (current stream number, lifetime broadcast hours/time, daily and weekly streaks, lifetime unique chatters, lifetime messages, next stream and broadcast hour goals), Game Plan (playing now, next scheduled, counts) and weather (temperature, condition, icon, high/low, wind; needs weather enabled in StreamPulse). Slideshow state needs the overlay open in OBS or a browser. Timers and goals appear automatically.

Milestone estimates are available as `milestone_stream_estimate_days`, `milestone_hours_estimate_days` and `milestone_chatters_estimate_days`. Values are approximate and empty when no estimate is available.

`chat_subscribers` counts new and returning subscribers in the collected session. Updated StreamPulse records native Twitch EventSub subscriptions even without a shared chat message, alongside SSN events; nearby duplicate notifications share one count. Existing buttons and variable references keep working.

Same-viewer subscription notifications within two minutes share one count and alert; later shared messages enrich tenure without replaying the alert. Native Twitch gift batches preserve their full count. While native gift delivery is active, SSN adds pending recipient details without generating duplicate alerts; otherwise SSN remains the fallback. Anonymous gifts are attributed to Anonymous, not the recipient. Existing queue/replay controls and variable IDs are unchanged; historical alerts are not rewritten.

Prime/paid alert selection uses explicit native chat-notification `is_prime` or SSN's Prime announcement details. Native tier `1000` alone cannot distinguish them. With native chat announcements or SSN available, basic events update counts/goals immediately, while renewal alerts wait for an announcement/shared resub. Native chat notifications use `user:read:chat`; SSN remains a source of details. No new Companion action or variable ID is required.

For confirmed old mistakes, StreamPulse's administrative `POST /api/alerts/history/correct` supports preview (`dryRun:true`), full-record `expected` conflict checks, backup and audited originals. Follow the in-app Docs/API instructions before applying with `dryRun:false`. No replay, live update, count/rule/queue change or new module variable occurs. Refresh Studio/OBS queue dock to see corrected/duplicate statuses. Duplicate event replay is blocked; canonical event replay uses corrected data, while recent/exact-alert replay retains original playback history. This is POST-only maintenance, deliberately not a Companion GET trigger or module action.

**Community insights:** `community_insights_status` and the matching feedback show `off`, `scanning`, `ready`, `error` or `unavailable`. Status refreshes every 30 seconds and becomes unavailable when StreamPulse or its status endpoint cannot be reached. Enable tracking in StreamPulse Config Editor and configure individual messages in Chat Bot; no per-person data is exposed.

Stream title/category variables retain current Twitch metadata while offline. Updated StreamPulse records title/category history only during live broadcasts, with one starting state at the actual broadcast start. No action or variable IDs change.
